# Fill Mode (PRISM-VIEW) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A window-filling "fill mode" for the Twitch player page (video and chat fill the window, PRISM chrome hidden), a "fullscreen both" button, and chat text-size controls, all remembered.

**Architecture:** `ChatDock` owns a persisted fill flag and an unsaved fullscreen flag. When either is on it turns its row into a fixed full-window layout with CSS classes (the player node never moves) and sets a `data-fill` attribute on the page root. The shell pieces (header, panels, rail, rain canvas, the page sections below the dock) carry a `fill-hide` class that the attribute hides, so nothing is unmounted and nothing needs shared state. Text size scales the chat with `transform: scale()` from outside, saved in one key that every window follows through the `storage` event.

**Tech Stack:** React 19, TypeScript, Tailwind v4, Vitest + Testing Library (jsdom), the Fullscreen API.

**Spec:** `docs/superpowers/specs/2026-11-04-fill-mode-design.md` (read it, especially "My calls" 1-18)

## Global Constraints

- **The player node never moves.** Fill and fullscreen are CSS class changes on existing elements: no portal, no re-parent, no `key` change. A test asserts the same DOM element before and after flipping.
- **Nothing over the embed.** Hidden chrome is `display: none`, not lowered. Controls sit beside the player (chat header, the strip). The fill row's background is behind the player. **No transition or animation** on the player wrapper's size or position.
- **Always a way out:** a visible "exit fill mode" button exists with chat docked, hidden and popped out. Esc is best effort only.
- **Hide, never unmount** the header, rail, panels, rain canvas, or the sections below the dock.
- **Text size:** `transform: scale(s)` with the box sized to `1/s`; never CSS `zoom`. Applies at `md` (768px) and wider in the main window, always in the pop-out.
- **Fullscreen** is requested on the dock row from a click, in both modes; sync only when `document.fullscreenElement === dockRow`; Esc leaves fullscreen first.
- **Widths:** fill applies at `md`+ when chat is docked, at any width when chat is hidden or popped out.
- **Storage:** new keys in `STORAGE_KEYS` (`LOCAL_FILL_MODE: 'prism_fill_mode'`, `LOCAL_CHAT_SCALE: 'prism_chat_scale'`), all access in try/catch, garbage means the default.
- **Accessibility:** real labelled buttons with a visible focus state; a toggled button stays mounted so it keeps focus.
- **Tailwind needs literal class strings** (it cannot see classes built from pieces), and `erasableSyntaxOnly` is on (no parameter properties or enums).
- Run tests with `node ./node_modules/vitest/vitest.mjs run <path> --maxWorkers=2` and judge by the printed `Tests` line; run `pnpm run build` before finishing a task (vitest does not type-check). jsdom has no Fullscreen API, `setPointerCapture`, or real `matchMedia`: stub what a test needs.
- Commits carry no `Co-Authored-By` trailer. **Do not push, open a PR or merge without the owner's say-so.** Branch `feat/fill-mode` is stacked on `feat/chat-autoplay-ergonomics` (PR #55).
- The Volume Meter extension is owner-run acceptance only; no selector may assume what else is a child of `body` or of the player's parent.

## Review Focus

Failure modes the spec implies that the plain tests would not reach; each has its test in the named task.

1. A saved fill value that is garbage, or the dock not being mounted (hub, YouTube, HLS pages): only the exact string `true` counts, and the page root attribute exists only while `ChatDock` is mounted (Tasks 2, 3).
2. A narrow window with fill remembered: chat docked must keep the stacked layout, chat hidden or popped out must fill, and an exit button must be visible either way (Tasks 3, 5).
3. Fullscreen edge cases: API missing (button hidden), request rejected (nothing changes, nothing throws), Twitch's own fullscreen button fullscreening the iframe (must not flip our state), fullscreen with chat hidden (Tasks 4, 5).
4. A saved text size that is garbage or out of range; a remembered large size on a narrow main window; the pop-out following a change, including a pop-out loaded directly with no owner; the strip that holds the buttons must not itself be scaled (Tasks 6, 7, 8).
5. Flipping modes remounting or moving the player (stream restarts, autoplay re-decided), or anything landing over the embed (Tasks 3, 5).
